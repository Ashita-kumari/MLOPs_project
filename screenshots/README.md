# Screenshot Checklist and Capture Guide

Use this folder for genuine screenshots captured while running the project on the Windows machine. Take screenshots yourself; do not recreate output or present an unrun step as completed. Use synthetic example inputs only. Before sharing, check that screenshots do not show real patient data, usernames, email addresses, tokens, passwords, private repository URLs, or unrelated work information.

## How to capture

1. Run the indicated command or workflow and wait for it to finish.
2. Keep the application/window title, URL or terminal command, relevant result, and enough surrounding context visible to explain what the screenshot proves.
3. Capture the full relevant window where practical; crop unrelated desktop areas, but do not crop away errors, warnings, timestamps, model/run identity, or status needed to interpret the evidence.
4. Save PNG files in this folder using the filenames below. If you take multiple attempts, keep the final successful capture and do not delete a meaningful failure if you plan to discuss troubleshooting.
5. Tick a checklist item only after you actually have that evidence. A screenshot of configuration alone is not proof that a workflow or deployment ran.
6. Add the completed images to `REPORT.md` with captions and a short explanation of what each proves.

## Report captions

For each included image, add a figure number, concise caption, the command or page shown, and the result it demonstrates. State whether evidence came from Windows local execution, Docker, Kubernetes, or GitHub Actions. Keep only evidence relevant to the final report; do not pad the report with duplicate screenshots.

The assignment also asks for a short pipeline video. A video is separate from screenshots; save it outside this folder unless your submission instructions say otherwise. The final report must be your own explanation and must meet the required 10-page format.
